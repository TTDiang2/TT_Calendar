# 多端同步配置指引（Gitee / GitHub 私有仓库）

> 一次配置，每台电脑各做一遍。全程约 5 分钟。
> 两个通道功能完全等价，只是「数据存在哪」不同。

## 现成的一套（2026-11-24 已建好，两台机器都填这个）

| 项 | 值 |
|---|---|
| 同步方式 | **Gitee** |
| 仓库 | `TTDiang/tt-calendar-data`（私有，匿名访问 403） |
| 分支 | **`master`**（不是 main！） |
| 私人令牌 | 与 GitHub secret `GITEE_TOKEN` 同一串；**若已吊销请重新生成再填** |
| 已上传 | 2687 行（待办 1609 / 日程 225 / 染色 486 / 标记 135 / 倒数日 8 …） |
| 远端快照 | `ttc-sync.bin.gz`，约 137 KB（gzip，含全部表） |

- **本机（有数据的那台）**：设置里已配好，点「立即同步」即可增量。
- **新机器**：填上面四项 → 「测试连接」→ 「立即同步」→ 弹窗选
  **用远端覆盖本地**（全新机器本地是空的，覆盖没有损失）。
- 数据是明文 JSON 压成 gzip 放在**私有**仓库里，仓库千万别改公开。

## 0. 选哪个

| | Gitee（码云） | GitHub |
|---|---|---|
| 境内直连 | ✅ 不需要代理 | ❌ 多数网络不可达 |
| 注册成本 | 手机号 + 实名 | 邮箱 |
| 私有仓库 | 免费 | 免费 |
| 单次同步请求 | 2 次（单文件快照） | 6 + 表数量 |
| 适合谁 | 大陆网络环境 | 海外或有稳定代理 |

> 两个通道**可以随时切换**：本地合并基准（`data/sync_base/`）与通道无关，
> 换通道后首次同步会把它当成一个全新的远端、重新上传一次快照。

## 1. Gitee（推荐国内使用）

### 1.1 建数据仓库（只需做一次）

1. 打开 <https://gitee.com/projects/new>
2. 仓库名称随意，例如 `tt-calendar-data`
3. 选择 **私有**（必须！数据是明文 JSON）
4. **不要**勾选「使用 Readme 文件初始化这个仓库」
5. 创建

> 记下仓库的完整路径，形如 `你的用户名/tt-calendar-data`。
> 仓库名请用英文、数字或 `-_.`（应用里的校验只放行这些字符）。

### 1.2 生成私人令牌

1. 右上角头像 → **设置** → 左侧 **私人令牌** → **生成新令牌**
2. 描述随意；权限勾选 **projects**（仓库读写）
3. 生成后立刻复制（只显示一次）

### 1.3 在 TT Calendar 里配置（每台电脑）

1. 设置 → 「数据同步」区块 → 同步方式选 **Gitee**
2. 仓库填 `你的用户名/tt-calendar-data`
3. 分支：Gitee 新仓库默认是 `master`。**先填 `master`**；若你的仓库确实用 `main` 再改成 `main`
4. 私人令牌粘贴进去（保存后用 Windows 加密存在本机，界面不再显示；留空表示沿用已存的）
5. 点「测试连接」→ 应显示「连通正常」
   - 提示里若出现「仓库默认分支是 …」，按它把分支改掉再测一次
6. 点「立即同步」：
   - **第一台电脑**：仓库是空的 → 自动上传全部数据（显示「首次初始化完成」）
   - **第二台及以后**：检测到远端已有数据 → 弹出选择：
     - **合并两边并上传（推荐）**
     - **用远端覆盖本地**
7. 勾选「启动时自动同步一次」（默认开启）

## 2. GitHub

### 2.1 建数据仓库（只需做一次）

1. 打开 <https://github.com/new>
2. Repository name 随意，例如 `tt-calendar-data`
3. 选择 **Private**（必须！）
4. **不要**勾选 README / .gitignore / license
5. Create repository

### 2.2 生成 PAT（fine-grained，最小权限）

1. 打开 <https://github.com/settings/personal-access-tokens/new>
2. Resource owner：你自己
3. Repository access：**Only select repositories** → 选中刚建的仓库
4. Permissions → Repository permissions → **Contents: Read and write**（唯一必需）
5. 生成后立刻复制 `github_pat_...`

### 2.3 在应用里配置

同 1.3，同步方式选 **GitHub**，分支通常 `main`。

## 3. 日常使用

- 改完数据后手动点「立即同步」，或等下次启动自动同步
- 同步报告：`拉取 N · 推送 M · 冲突 K · 删除 D`（冲突 = 两台改了同一条，按修改时间新者胜）
- 每次同步 = 仓库里一个 commit，网页可看每次改了什么、可回滚
- **Gitee**：仓库根目录只有一个 `ttc-sync.bin.gz`（gzip 后的整份快照）
- **GitHub**：`data/` 下每表一个 JSON，可读

## 4. 常见问题

| 现象 | 处理 |
|---|---|
| Gitee：「私人令牌无效或过期（401）」 | 令牌被删/过期 → 重新生成，粘贴保存 |
| Gitee：「拒绝访问（403）」 | 令牌没勾 **projects** 权限；或触发限流（等几分钟） |
| Gitee：「分支 main 不存在」 | 新仓库默认分支是 `master`，把设置里的分支改成 `master` |
| Gitee：「远端快照不是本应用写的」 | 仓库里的 `ttc-sync.bin.gz` 被手动改过。删掉它重新同步即可（本地数据不受影响） |
| GitHub：「PAT 权限不足（403）…Contents 设为 Read and write」 | fine-grained PAT 的 Contents 是只读。编辑 PAT → Permissions → Contents → Read and write（勾了仓库 ≠ 给了写权限，两处要分别设置） |
| GitHub：「PAT 无法访问仓库（404）」 | PAT 没勾选数据仓库（先建 PAT 后建仓库时必然踩到）。编辑 PAT → Repository access → 勾选该仓库 |
| 「并发冲突」 | 两台同时在同步 → 再点一次（引擎也会自动重试一次） |
| 换电脑后令牌解密失败 | DPAPI 绑定原机器 → 新机器重新粘贴令牌即可 |
| 想重新初始化远端 | 清空仓库内容（或删库重建），删本机 `data/sync_base/`，再「立即同步」 |

## 5. 安全边界

- 数据**明文**存在你自己的私有仓库里（Gitee 上是一个 gzip 快照，解压即 JSON）
- 令牌用 Windows DPAPI（当前用户 + 本机）加密后存本地 SQLite，永不上传、不同步、界面不回显
- 令牌只授权一个仓库，泄露也动不了你的其他仓库
- 换通道不会动本地数据；`data/sync_base/` 只影响「哪边算变更」的判断
