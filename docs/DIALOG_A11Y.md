# 对话框可访问性：一次组件库探针的结论与遗留缺陷

2026-10 做过一次 shadcn/ui 升级探针。结论是**不做整体升级**：视觉上没有可感知改善，为此引入 Radix + 令牌层 + 十几个组件的迁移成本不划算。

但探针顺手测出了现有 `Modal` 的 7 个真实缺陷。这些和组件库无关，可以用几十行代码独立修掉。这份文档就是那次的实验记录，留作以后动手的依据。

回退点：`checkpoint/pre-shadcn-20261019`（提交 `15892e8`）。探针实验的源码已不在仓库里。

---

## 一、测到了什么

同一个探针脚本，在升级前和升级后各跑一遍。环境是 Windows + 系统 Chrome（`playwright-core`，不用下载浏览器）。

| 指标 | 升级前 | 升级后 |
|---|---|---|
| `role` | `null` | `dialog` |
| `aria-labelledby` / `aria-label` | 无 | 有 |
| 打开时焦点进入弹窗 | 事件弹窗 ✓ / 设置弹窗 **✗** | ✓ / ✓ |
| 焦点陷阱（连按 Tab 不跑出去） | 事件弹窗 **✗** / 设置弹窗 ✓（不稳定） | ✓ / ✓ |
| Esc 关闭 | **✗ / ✗** | ✓ / ✓ |
| 打开时锁定背景滚动 | **✗** | ✓ |
| 关闭后焦点归还触发元素 | **✗** | ✓ |

像素差异（升级后 vs 升级前，状态已归一化）：月视图 0.27%、事件弹窗 1.96%、设置弹窗 9.63%、壳层 4.36%、窄视口 4.65%。

盯着差异图看，壳层那 4.36% 只有两种来源：日历格圆角的抗锯齿，和设置按钮上多出来的一圈焦点环（这是焦点归还修好之后应有的表现）。**没有一处颜色或布局变化**——因为令牌值是照着现有 `gray` 色阶取的。

所以"没有改善"这个判断是准确的：升级买到的是交互和可访问性，不是观感。

## 二、7 个缺陷

按影响排序，前三个是键盘用户会直接撞上的。

1. **Esc 关不掉弹窗。** 两个弹窗都不行。键盘用户打开弹窗后只能靠鼠标点关闭按钮，或者点遮罩。
2. **事件弹窗没有焦点陷阱。** 连按 Tab，焦点会跑到弹窗背后的日历上，继续按还能操作背景里的元素。
3. **设置弹窗打开时焦点根本没进去。** `document.activeElement` 还停在触发按钮上，屏幕阅读器不会读到弹窗内容。
4. **没有 `role="dialog"`，也没有 `aria-labelledby`。** 辅助技术无法识别这是一个弹窗，也不知道它叫什么。
5. **打开时背景能滚动。** 弹窗开着，鼠标滚轮滚的是背后的日历。
6. **关闭后焦点掉到 `<body>`。** 下一个 Tab 从页面最开头重新开始，而不是回到刚才那个按钮。
7. **点击遮罩关闭依赖手写的 `onClick`。** 键盘和屏幕阅读器用户没有等价入口（有 Esc 之后这条才真正成立，见缺陷 1）。

对应代码：`frontend/src/components/ui/Modal.tsx`，全文 46 行。

## 三、以后怎么修（不引入任何依赖）

现有 `Modal` 的签名是 `{ title, children, onClose, width }`，9 个调用点都不需要改。改动全部落在 `Modal.tsx` 内部：

- **语义**：外层容器加 `role="dialog"`、`aria-modal="true"`，`<h2>` 给一个 `id`，容器用 `aria-labelledby` 指过去。标题内容由调用方传 `title`，天然唯一，用 `useId()` 生成 id 即可。
- **Esc**：`useEffect` 里挂 `keydown`，`e.key === 'Escape'` 时 `onClose()`，清理函数里解绑。
- **初始焦点**：挂载后把焦点移到弹窗内第一个可聚焦元素；没有可聚焦元素时聚焦容器（容器需要 `tabIndex={-1}`）。
- **焦点陷阱**：每次 Tab 时重新查一遍弹窗内的可聚焦元素（不要缓存，弹窗内容会变），在首尾之间循环。
- **滚动锁定**：打开时 `document.body.style.overflow = 'hidden'`，卸载时还原原始值（**存原值而不是置空**，否则会覆盖别处的样式）。
- **焦点归还**：挂载时记下 `document.activeElement`，卸载时用 `queueMicrotask` 延后一帧再 `focus()`。

### 两个踩过的坑

**换个组件库并不会自动解决焦点归还。** 实验里换成 Radix Dialog 之后，关闭弹窗焦点依然掉到 `<body>`——因为本项目是父组件条件渲染打开弹窗的，没有 `DialogTrigger`，Radix 没有可归还的目标。最后是手动在挂载时记录、卸载时归还才修好。所以这条无论用不用组件库都得自己写。

**焦点归还要延后一帧。** 直接在卸载的清理函数里同步 `focus()`，目标节点可能正在被 React 移除，焦点会被吃掉。放进 `queueMicrotask` 才稳定。

## 四、探针本身的坑

这轮排查里，第一版的像素数字是**错的**，值得记下来。

- **状态没归一化，比的是状态不是样式。** 升级前的版本 Esc 关不掉弹窗，探针按完 Esc 直接截图，于是基线里所有截图都带着遮罩层和弹窗，和升级后（已关闭）的截图整屏错位——看上去像"整个界面都在动"。修法：截图前把所有滚动容器的 `scrollTop` 归零，并且强制确认弹窗已关闭。
- **同代码连拍两次，MD5 完全相同。** 这说明探针是确定性的，一旦出现差异就是真差异，不能拿"渲染噪声"搪塞自己。这条反而让结论更硬。
- **模态选择器不能混写。** `[role="dialog"],[aria-modal="true"],.fixed.inset-0` 放在同一个选择器列表里，`querySelector` 会先命中遮罩层（它也匹配 `.fixed.inset-0`）。要分两段：先试语义选择器，没有再退回类选择器。
- **先截图，再探测。** 探测流程末尾会按 Esc 关弹窗，顺序反了就只能拍到关掉之后的空页面。
- **ESLint 会扫 `scripts/*.mjs`。** 探针里用 `document`、`Image` 是正常的（那些代码在浏览器上下文里跑），但默认配置会报 `no-undef`。需要在 `eslint.config.js` 的 `ignores` 里排除 `scripts/**`。
- **窗口宽度 8px 阈值对阴影和抗锯齿很敏感。** `delta > 12` 的判据下，投影柔化一点点就会大面积计数，看百分比之前先看差异图。

## 五、复现

前后端都要起着（回退后的版本没有打包，直接跑 dev）：

```bash
# 后端
python -m uvicorn backend.main:app --port 8000

# 前端
cd frontend && npm run dev
```

注意 vite 只绑 IPv6，浏览器要开 `http://localhost:5173`，`127.0.0.1` 打不开。

```bash
cd frontend
npm i -D playwright-core     # 回退后这个依赖不在 package.json 里
node scripts/visual-probe.mjs --out ../.visual-probe/after --base http://localhost:5173
node scripts/diff-shots.mjs --before ../.visual-probe/before --after ../.visual-probe/after
```

探针脚本留在 `frontend/scripts/`（未纳入版本管理）。它们不参与构建，只用于以后验证弹窗行为。不需要的话直接删掉两个 `.mjs` 即可。

脚本里的几个约定：

- 用 `localStorage.setItem('tt.lang', 'zh-CN')` 跳过首次语言引导页
- 截图输出到 `.visual-probe/`；回退时 `.gitignore` 里的对应条目一并被撤掉了，重新用之前记得加回去
- `diff-shots.mjs` 会额外输出差异包围盒和出现最多的颜色迁移对，判断"变在哪"比百分比有用
