# TT Calendar 顶层架构

> **给 AI 模型的指引**：动手改任何与"图层/涂色/点点/事件/日程"相关的代码前，**先读本文档**。TT Calendar 的核心设计是"以颜色标记为主题的日历"，涂色和点点是两条独立的标记链路，混用会导致事件/涂色/点点互相污染（典型 bug：打卡被当成事件、自定义点点图层不显示色点、涂色选择里出现自动图层）。

## 核心理念

TT Calendar 是一个以**颜色标记**为主题的日历。有两种颜色标记方法：**涂色**、**点点**。

## 一、涂色（背景染色）

直接在各种视图里对应的那一天涂上对应的颜色。非常直观。

### 三种涂色逻辑

| 逻辑 | 说明 | 颜色 | 例子 |
|---|---|---|---|
| **打卡**（solid） | 用户自定义图层，**只允许涂一种颜色** | 单色 | 早睡打卡、早起打卡、健身打卡 |
| **完成度**（graded） | 内置"充实度染色" + 用户自定义，**一种颜色五种色阶** | 5 档色阶 | 工作完成度、学习完成度 |
| **关联**（tag/auto） | 自动从倒数日、待办等其他地方关联过来的涂色 | 单色或 5 档色阶 | 待办忙度（predict 琥珀/done 钢蓝）、重要日期 |

### 涂色的存储与展示规则

- **所有涂色都不在右侧边栏形成"事件"**（打卡不是事件！涂色标记独立存储，不进 events 表）
- **所有具有五种色阶的涂色**（所有完成度涂色 + 一部分关联涂色）**需要在右侧边栏详细信息中标注涂色条**（显示色阶档位）
- 单色打卡涂色不需要在右侧边栏显示条目

### 图层颜色锁定规则

- 图层创建时确定 mode + color/palette
- **该图层的新增涂色条目只能使用图层预定的颜色/调色板**
  - 例：充实度染色设 5 档绿色 → 后续新增条目只能从 5 档绿色里选，不能选黄色
  - 例：早起打卡图层设青色 → 新增条目只能青色或无色
- 图层颜色只能在**设置页**修改（影响该图层全部条目），**右侧边栏/涂色按钮处不能改**

### 自动涂色图层（不可手动新增）

这三个图层是自动计算/关联的，**不允许自定义新增**，不出现"新增涂色"选项：
- `holiday` 公共节假日
- `important` 重要日期
- `todo` / `todo_done` 待办忙度（predict/done）

## 二、点点（左上角色点 + 侧栏条目）

直接在各种视图里对应的那一天的**左上角**标上对应颜色的点点。

### 点点图层的两类产出

| 图层类型 | 右侧边栏产出 | 例子 |
|---|---|---|
| **日程**（schedule） | 形成"**日程**"（带起止时间） | 工作、课程、运动、玩耍、其他 |
| **其他点点图层** | 形成"**事件**"（无时间） | 集思录、自定义事件类点点 |

### 日程（schedule）的分类

"日程"已经拆分成 5 个 category，**不再有顶层"日程"图层**：
- work 工作
- course 课程
- sport 运动
- play 玩耍
- other 其他

新建点点图层时可归类为"日程"（→ 存 schedule_items，带 category）或"事件"（→ 存 events）。
**判断一个点点图层是否是日程类，依据是图层 config.category 是否属于日程分类，而不是 layer_id 前缀。**

## 三、关键设计约束（避免回归的红线）

1. **涂色 ≠ 事件**：涂色标记（打卡/完成度）走独立的 coloring/marks 存储，**绝不**进 events 表。events 表只存"点点图层中的事件类"。
2. **自动涂色图层不可手动标记**：holiday/important/todo/todo_done 不出现在"新增涂色"的下拉选项里。
3. **图层颜色锁定**：涂色条目颜色由图层决定，右侧边栏不能自由选色（仅设置页可改图层颜色）。
4. **schedule 判断不用 layer_id 前缀**：用 `config.category` 判断。自定义图层 layer_id 一律 `custom_*`，不依赖前缀区分类型。
5. **打卡唯一性**：同一打卡图层同一天只能有一条标记（不允许重复打卡），且必须可删除。
6. **"日程"图层不可选**：涂色/点点选择器里不应出现顶层"日程"图层（旧的 layer_id='schedule' AM/PM/EV 结构已弃用），只出现 5 个拆分后的日程分类。
