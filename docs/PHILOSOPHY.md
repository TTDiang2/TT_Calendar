# TT Calendar 设计哲学

> 本文档是所有后续设计决策的最高参照。与 ARCHITECTURE.md（技术架构）、SYNC_PROTOCOL.md（同步协议）配合阅读。
> 当用户提出的需求与本文冲突时，先在本文层面厘清，再动代码。

## 1. Agent-First：这个应用假设用户永远有一个 Agent

TT Calendar 不是给「普通用户」的通用产品，是给「一个拥有 AI agent 的个人用户」的**高度可定制日历底盘**。

- 技术选型本身就是这个哲学的体现：**Python 后端**（agent 最擅长的修改语言）、**丰富的 docs**（agent 的操作手册与踩坑记录）、**数据仓 + 代码仓分离**（agent 改代码不影响数据）
- 一切「用户想要新功能」的场景，默认路径不是等开发者发版，而是：**用户描述需求 → agent 读 docs → agent 改代码 → 本地 rebuild**
- 因此 docs 不是附属品，是一等公民。每个非显然的设计决策、每个踩过的坑都必须沉淀进 docs（用户哲学：**遇到问题先查 docs，docs 没有就先记录再修复**）
- 「订阅」机制（§3）是这个哲学的直接产物：新数据源不需要等应用支持，用户登记描述、agent 现场适配

## 2. 先打磨、后迁移（D 计划冻结条款）

> 2026-08 用户裁定：「多打磨几轮，直到把 Python 版本的应用打磨得足够好了再去做 PWA 的迁移，这样总体而言还节省工作量」。理由：PWA 迁移要移植的是**数据层与全部业务语义**，Python 版每遗留一个未修的 bug / 未厘清的设计，迁移时都会被放大成「移植一个错误」——先打磨 = 总工作量更省。

- **D 系列（PWA）计划冻结**：PLAN_PWA.md 保留为未来蓝本，D0 已完成的地基（SYNC_PROTOCOL.md + golden vectors + core/types.ts）不回滚、继续作为 Python 实现的行为锚，但 D1 起全部暂停
- 每当用户要求推进 D 计划时，agent 必须先用 question tool 问：**「你觉得 Python 版本的应用已经打磨得足够好了吗？」**，并列举当前已知的遗留问题清单提醒
- 解冻条件（满足才重启 D）：功能缺口清零（订阅/同步/农历等已列事项全部落地）、连续两周无架构级改动需求、用户明确裁定「打磨完成」

## 3. 订阅制：一切外部数据源都是订阅

早期为快速使用把「集思录投资日历」硬编码内嵌，这是**技术债**。正确的心智模型：

- **外部数据源 = 订阅**。应用本体只提供「订阅框架」：开关、自动拉取策略、适配状态展示
- **两类订阅**：
  - **内置订阅**（集思录）：适配代码已存在于代码库，开箱即用
  - **自定义订阅**：用户在面板登记（网址 + 自定义标题 + 自然语言描述的抓取规则），状态为「待适配」；由用户的 agent 读登记信息后现场写适配代码（见 §3.1）
- **拉取策略逐订阅可配**：默认「打开日历时自动拉取」，但一年一更的日历可关掉自动拉取改为手动
- 订阅产生的是**派生事件数据**（events 表，source=订阅标识），不参与数据同步（各设备自行拉取，见 §4）

### 3.1 Agent 适配流程（新订阅的接入方式）

```
用户在订阅面板登记（URL + 标题 + 自然语言规则）
  → 面板显示「待适配」状态 + 提示：请把 TT_Calendar 文件夹用您的 agent 软件打开，
    并提醒 agent 有新的订阅要做适配
  → agent 打开 TT_Calendar，读 docs/AGENT_GUIDE.md（agent 操作总入口）
     → 读 subscriptions 表中 status='pending' 的登记信息（URL/规则描述）
     → 按 docs/SUBSCRIPTION_SPEC.md 的适配规范实现 source（抓取器）
     → 把订阅状态置为 active
  → 前端刷新即见新订阅开关
```

登记信息是**给 agent 读的结构化需求单**，字段设计以此为目标（URL、示例数据、抓取频率建议、输出期望）。

## 4. 双轨同步：数据走数据仓，代码走代码仓

- **数据同步**（已实现，SYNC_PROTOCOL.md）：用户数据 ↔ GitHub 私有数据仓（tt-calendar-data），行级三方合并
- **代码同步**（agent 时代的必然需求）：agent 对程序的修改 ↔ GitHub 代码仓（TT_Calendar 本身就是 git 仓库）。两台机器想让「程序改动」互通 = 正常的 git push/pull；PWA 前的 Python 阶段不内置程序自动同步（git 已是最好的工具，应用内重复造轮子收益为负）
- 原则：**应用永远不碰自己的代码仓**（不做自动 commit/push），这是 agent / 用户显式操作的领地

## 5. 同步触发的完整生命周期（打磨目标）

打开时自动拉 + 手动按钮 + **关闭前自动同步**（窗口关闭被拦截 → 完成一次同步 → 提示「正在同步，同步完成后自动退出」→ 自动退出）。用户的修改永不为零散丢失创造窗口。

## 6. 日历的本地化根：农历

中国用户的日历缺农历不可用。农历是一等公民：日期展示带农历，倒数日支持**农历重复**（春节=正月初一、七夕=七月初七，公历日期年年不同，重复逻辑遵循农历而非 365 天周期）。
